# Source map

The port follows nanoclo `4cdd12f`; files translated from upstream carry source
notices. The production checker uses Fortran modules and implementation
fragments in `include/`.

| Area | Fortran implementation | Rust counterpart |
|---|---|---|
| Names, levels, expressions | `src/names.f90`, `src/levels.f90`, `src/expr.f90` | `name.rs`, `level.rs`, `expr.rs`, `LeanDag` |
| NDJSON and declaration records | `src/json.f90`, `src/parser.f90`, `include/parser_decl.inc` | `parser.rs` |
| Environments and read-set projection | `src/closure.f90`, `src/read_sets.f90`, `include/eq_mod.inc` | `closure.rs` |
| Values, spines and memo tables | `src/nbe.f90`, `src/spines.f90` | `nbe.rs` |
| Evaluation, unfolding and readback | `include/nbe_eval.inc`, `include/nbe_inductive.inc`, `include/readback.inc` | `nbe_eval.rs` |
| Conversion and speculative probes | `include/nbe_conv.inc` | `nbe_conv.rs` |
| Closure/type inference | `include/tc.inc`, `include/nbe_type.inc` | `tc.rs`, `nbe_eval.rs` |
| Inductives and recursors | `include/inductive_*.inc`, `src/inductive_state.f90` | `inductive.rs` |
| Literals and Quot | `src/bignums.f90`, `include/nbe_nat.inc`, `include/nbe_string.inc`, `include/quot.inc` | literal and Quot routines |
| Declaration scheduling | `include/parallel.inc`, `include/kernel_support.inc` | serial/parallel drivers in `tc.rs` |

## Storage and declaration lifetime

Kernel object fields are stored in parallel allocatable integer arrays. References are 32-bit
indices, with zero reserved for absence. The shared hash table uses four-word
keys, open addressing and linear probing. Storage capacity grows by doubling; arithmetic
hash mixing uses widened and masked intermediates. The optimized table caches
its capacity mask and load threshold and uses a cheaper bucket-placement hash.
Structural object hashes, full-key equality and kernel cache semantics are unchanged.

After parsing, exported Expr arrays and their interner become immutable module
storage. Each worker stores scratch expressions after the export index range;
getters dispatch by index. The workers retain independent mutable storage and
memo tables. Declaration-index cutoffs preserve environment visibility even
when independent checks execute out of order.

Parallel workers reset scratch expressions and constant caches for each
declaration, matching nanoclo's nonpersistent parallel mode. Serial checking
retains these caches and resets them at a 2^22-expression scratch epoch.
Per-declaration values, environments and conversion caches reset in both modes.

Export ID maps use dense integer arrays for ordinary sequential IDs and a
sparse hash fallback for large/out-of-order IDs. The CLI streams input through a 1 MiB buffer, growing it only for a longer
individual record. The parser releases staging maps and JSON tokens before kernel
checking. Read-set caching
stores only visited expressions; its reset cost is independent of the full
export's expression count.

The first bounded Mathlib run, on the earlier parser-map implementation, failed
allocation with exit 3 during parsing (17,157,416 KiB peak RSS). Its
[raw evidence](development-memory-failure.tar.gz) is preserved with the old
binary hash. Compact index maps fixed this; the pre-optimization SoA baseline
accepts the same Mathlib input under the same limit, at 14,990,840 KiB peak RSS.
The [optimization report](optimization-report.md) records the current binary’s
separate full-corpus measurements.

## Checking fidelity and layout

The decision order in conversion, lazy unfolding, read-set projection,
Nat-literal deferral and speculative probe budgets follows the pinned source.
[Counter evidence](fidelity-summary.json) compares all 26 counters for every
Init declaration and every accepted small-corpus stream. This provides
algorithm-fidelity evidence beyond matching verdicts.

The AoS experiment is generated by `scripts/make_expr_aos.py`: it changes Expr
fields into an allocatable array of derived-type nodes, including immutable
export storage. Accessors and growth change with that representation; all
kernel routines, other object storage, flags and inputs stay the same. Its independent
Init counter gate checks that this transformation preserves behavior.
